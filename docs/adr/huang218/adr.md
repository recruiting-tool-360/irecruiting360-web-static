# irecruiting360-web-static：架构决策

最后更新：2026-11-20

## ADR-001：AI 初始化仅落地协作与文档治理

状态：已采纳

### 背景

本仓库是 Quasar/Vue Web SPA 与 Electron 桌面客户端，不是 Java/iHR360 后端服务。用户要求“AI 初始化该项目”，但没有要求新增模型网关、Prompt 存储或异步生成服务。

### 决策

本次初始化只建立 `AGENTS.md`、按维护者拆分的文档体系、项目架构、决策、路线图、数据模型、需求与 AI 日志；不创建 Java 模块，不引入模型 SDK，不生成不可运行的 AI 服务骨架。

### 后果

- AI 协作规则可以立即用于本仓库开发。
- 业务 AI 能力继续由既有后端接口提供，前端只维护调用、任务和展示契约。
- 若后续需要新增服务端 AI 基座，应另立需求并先确定目标仓库、技术栈、模型端口、持久化和部署边界。

## ADR-002：保留现有专题文档，新增维护者目录

状态：已采纳

### 背景

仓库已有接口、客户端、插件、自动化、发版和 V2.1 方案文档，分散在 `docs/` 根目录。直接移动会破坏链接、历史和团队引用。

### 决策

保留现有 `docs/*.md` 原位，并作为事实来源；新增文档按 `docs/<category>/<owner>/` 组织。新任务只在自己的维护者目录写入需求、日志和结论，读取时合并所有维护者目录。

### 后果

- 不产生大规模文档搬迁和引用破坏。
- 需要在 `docs/README.md` 维护专题入口和冲突规则。
- 后续若迁移旧文档，必须单独立项并检查引用影响。
