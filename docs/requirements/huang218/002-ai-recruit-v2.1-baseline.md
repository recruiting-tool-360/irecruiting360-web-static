# 002 AI 寻聘 V2.1 迭代需求基线

最后更新：2026-11-20

状态：评审中

## 背景

AI 寻聘 V2.1 的五份文档在提交 `6c8edf2` 中作为同一迭代需求方案引入，覆盖完整技术方案、接口设计、表设计、DDL/回退 SQL 和四项目交付排期。它们需要作为统一需求包读取，不能拆散成互不关联的背景资料。

## 基线版本

- Git 基线：`6c8edf2`，提交信息为 `fix(34326): i快招2.1需求方案`。
- 基线日期：2026-11-19 至 2026-11-20。
- 当前状态：技术方案、接口设计和表设计均标记为“待技术评审”。
- 本仓库范围：`irecruiting360-web-static` 中的 Web SPA 与 Electron 客户端，对应交付任务 `IHF-01` 至 `IHF-29`。

## 本仓库范围

- 建立客户端会话、心跳、断线恢复和错误模型。
- BOSS 登录态、账号/公司、职位列表和权益采集。
- 按 `clientSessionId + sessionEpoch` 建立任务 SSE 并展示日计划和执行状态。
- 改造手动搜索、任务执行、预筛、评分、打招呼、回复和附件简历链路。
- 隐藏迁移后的旧配置入口，保留只读兼容和回滚开关。
- 职位画像改为招聘权威源，并完成敏感日志、真机 E2E 和弱网验证。

具体任务和状态见 [V2.1 前端/桌面端实施账本](../../plans/huang218/001-ai-recruit-v2.1-frontend-delivery.md)。

## 非目标

- 不在本仓库执行 i 快招后端、招聘后端或招聘前端的数据库 DDL。
- 不替代四个项目的接口评审、权限设计和跨服务联调。
- 不把排期表中的工时或日期当作已经完成的事实。
- 不复制完整 DDL、表结构或接口正文到维护者目录。
- 不在评审完成前把候选方案提升为已采纳 ADR。

## 关键待确认

- 技术方案、接口设计和表设计尚未完成技术评审，正式开发前需确认最终版本。
- 技术方案提到 `docs/ai-recruit-v2.1-complete-technical-design.md` 和 `docs/ai-recruit-v2.1-technical-design-detailed.md`，但当前仓库中不存在这两个文件；它们只能作为外部历史来源线索，不能作为本轮可审计依据。
- i 快招后端、招聘后端和招聘前端的接口是否按排期可用，需要跨项目确认。
- DDL 的执行窗口、历史回填责任和回滚演练由对应后端负责人确认。

## 验收

- 五份原始文档均可从本基线进入，且不被移动或改写。
- 本仓库 29 个 `IHF` 任务均有状态记录入口。
- 评审前状态明确为“评审中/未开始”，不出现虚假完成状态。
- 新提炼的前端数据边界不超出待评审接口和技术方案。
- 文档链接、日期、编号和 Markdown 格式通过检查。

## 处理规则

1. 原始五份文档继续原位维护，作为评审和审计依据。
2. 评审结论、范围变化和冻结版本更新到本基线，不在多个文件重复维护总状态。
3. `IHF` 任务状态只在代码、测试或对应验证完成后更新；文档创建不等于功能完成。
4. 实现后从本基线向需求、实施日志、架构和数据模型回链证据。
5. 技术评审通过后，把已确认的跨模块决策提升为 ADR，再进入阶段性冻结。

已建立本基线、实施账本和文档入口。本次只完成需求治理，没有开始 `IHF-01` 至 `IHF-29` 的业务代码改造。

- 确认跨项目接口、DDL 执行和联调时间。
